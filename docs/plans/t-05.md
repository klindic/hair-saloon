# T-05 — Define the editorial colour, type and spacing tokens

**Goal:** `docs/design/tokens.md` exists, committed, naming every colour, spacing, radius and
type-scale value by role with light and dark defined together, with a verified WCAG AA contrast
ratio recorded for the disabled sign-in control (and the other pairings that matter), so T-07,
T-08, T-09, T-13 and T-14 fill in values instead of inventing them.

**Spec:** Agreed in design sync (Ren/Lena/Theo): editorial direction, Fraunces (variable,
standard-axes subset only) for display type, Work Sans (static 400/500/600) for body; a warm
off-black/paper palette with one clay accent restricted to the primary CTA, the selected-slot
ring and the universal focus ring; one `state-unavailable` token shared by taken/past/owner-blocked
tiles; one `state-error` token reserved for T-08's `unconfirmed` state only. Light colour values,
the font/package decisions and the submit-control dimensions (48px height, `space-5`/24px padding,
full-width layout) were fixed in that session. Dark-mode colour values, the full spacing/radius/
type scale, and the actual computed contrast ratios were explicitly left open — that is the design
work this ticket still has to do, not a gap to leave in the doc.

**Constraints:** Four engineers are about to build in parallel worktrees against this document —
ambiguity here becomes four different inventions. Token names are role-based, never named after
the one component they'll first appear in (`accent`, not `cta-button-colour`). This repo's `tools/`
scripts are plain Node ESM with no dependencies and no separate test files — see
`tools/check-contract.mjs` for the house style: a `failures` array, a `fail()` helper, non-zero
exit on any failure, wired into `npm run verify`.

## Repetition found, and what I did about it

Every later ticket that adds a colour pairing (a new tile state, a new text-on-background
combination) will need its contrast ratio checked. Computing that by hand, once per pairing,
forever, is exactly the manual chore `CONVENTIONS.md` says becomes a script in `tools/`. This repo
already has the precedent (`check-contract.mjs` stops `docs/sheet-template.md` and
`shared/contract.ts` from drifting apart silently) — `check-contrast.mjs` does the same job for
the token doc's own Contrast table, and it is a general-purpose CLI tool any future ticket can
reach for (`node tools/check-contrast.mjs <hexA> <hexB>`) rather than eyeballing a ratio or
trusting an LLM's mental arithmetic on gamma-corrected luminance, which is exactly the kind of
calculation worth getting from a script instead of a guess.

## Tasks

### T1 — Build the contrast-ratio checker

- **Specialist:** implementer
- **Why that one:** well-defined, bounded algorithm (WCAG 2.x contrast formula) with real
  correctness stakes and a clear test — not a rename, but not a design judgement call either.
- **Done when:** `node tools/check-contrast.mjs '#000000' '#FFFFFF'` prints `21`/`21.00`; an
  internal self-test asserts `#767676` on white is ≈4.54 (WCAG's own published example); doc-check
  mode exits 0 with a clear "doc doesn't exist yet" message when `docs/design/tokens.md` is
  absent (it is, until T2 lands); `npm run check:contrast` exists and is wired into `verify`;
  `npm run lint`, `format:check` and `typecheck` are all clean.
- **Files:** `tools/check-contrast.mjs`, `package.json`
- **Parallel:** no — T2 depends on this tool existing and must run after it

### T2 — Write the full token document

- **Specialist:** deep-implementer
- **Why that one:** real design tension, not application of an already-made decision — picking
  dark-mode colour values that preserve the warm editorial identity, a restrained radius scale
  that doesn't read as default-component-library, and a type scale that harmonises with the
  Fraunces sizes already fixed in session (56px hero, 28px section heading) is exactly the kind of
  call that's expensive to get wrong, since "does not look AI-generated" is a literal project
  success criterion this document either supports or undermines.
- **Done when:** `docs/design/tokens.md` exists with every item in its brief, `npm run
check:contrast` passes against it, and `npm run format:check` is clean.
- **Files:** `docs/design/tokens.md`
- **Parallel:** no — depends on T1 (needs the real tool to produce trustworthy numbers rather than
  hand-computed ones; gamma-corrected luminance arithmetic is exactly the kind of thing worth
  getting from a script instead of a guess)

### T3 — Critic pass

- **Specialist:** critic
- **Why that one:** adversarial, read-only check that the document actually satisfies its
  acceptance criteria and its own internal rules before this goes into a pull request — this is
  the one document four other tickets will build against without re-reading the ticket.
- **Done when:** a findings list exists (empty if none survive) covering: AC compliance, the
  accent/state-token usage rules, naming discipline, and that `npm run check:contrast` and `npm
run verify` actually pass.
- **Files:** none (read-only)
- **Parallel:** no — needs both T1 and T2 finished
