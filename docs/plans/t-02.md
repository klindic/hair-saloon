# T-02 — Serve a day's busy ranges without naming who booked them

**Goal:** `doGet` on the Apps Script endpoint answers an anonymous availability request with only
time ranges, built from a single sheet read, with no customer field ever reachable, and with
`slot_start`/`slot_end` always coming back as a salon-offset ISO string even when Sheets hands the
domain layer a `Date` instead of the string it was written as.

**Spec:** Agreed in technical grooming (see ticket #3). `main.ts` stays wiring-only; everything
that could be wrong about a row lives in `domain/`, which stays plain TypeScript with no Apps
Script globals; the only two files allowed to touch `SpreadsheetApp`/`Session`/`Utilities` are the
new `adapters/sheet-bookings-repo.ts` and `adapters/zone.ts`. `append` is declared but not
implemented — T-03 fills it in.

**Constraints:**

- `apps-script/src/domain/**` must stay globals-free and runnable under plain Node (`npm run
test:script`). Anything touching `SpreadsheetApp`, `Session` or `Utilities` goes in
  `apps-script/src/adapters/`.
- `shared/contract.ts` is not changed by this ticket — `BOOKINGS_COLUMNS`, `AvailabilityRequest`,
  `AvailabilityResponse`, `BusyRange`, `ErrorResponse`, `BookingRow`, `BookingStatus` already exist
  and are imported via the `@contract/contract` path alias (`apps-script/tsconfig.json`).
- One sheet read per request: `loadBookingsSnapshot()` is called once; the domain layer does one
  pass over the result, not a scan per check.
- The Zagreb offset is not fixed (CET/CEST), so nothing in this ticket hardcodes `+01:00` or
  `'Europe/Zagreb'` outside the one adapter that reads it from `appsscript.json` via
  `Session.getScriptTimeZone()`.
- Filenames are kebab-case in `apps-script/src/`.
- Do not implement `append`, do not take a lock, do not call `UrlFetchApp` — this ticket is the
  read path only.

## Design pinned here (so the two domain files agree on a seam neither owner will re-derive)

- `BookingsRepo.loadBookingsSnapshot(): unknown[][]` returns raw rows, header already stripped by
  the adapter. The repo does not parse rows — `parseBookingRow` does, in `domain/`.
- `Zone.offsetFor(instant: string): string` takes a UTC ISO instant and returns a signed offset
  like `+01:00`. `toSlotIso` computes the local wall-clock time itself (shift the epoch by the
  offset, read components with the UTC getters on the shifted instant, format manually) — it does
  not use the runtime's own local timezone anywhere, in Node or in V8-on-Apps-Script.
- `availabilityFor` validates the date, then does one pass over `snapshot`, calling
  `parseBookingRow` per row, skipping `cancelled`, skipping anything whose `slot_start` date
  prefix (first 10 characters — already salon-local once `toSlotIso` has run) doesn't match the
  requested date, and emitting `{ start, end }` for the rest.
- "Reads no booking data" on a malformed date is a wiring guarantee, not a domain one: `main.ts`
  calls `isValidCalendarDate` before it calls `loadBookingsSnapshot()` at all, not after.

Nothing here repeats more than once — one repo, one zone adapter, one mapping function reused by

## Tasks

### T2-A — `toSlotIso`, `parseBookingRow` and the two port interfaces

- **Specialist:** deep-implementer
- **Why that one:** this is the actual trap the ticket exists to close — Sheets silently hands
  back a `Date` with no offset information recoverable except through a port, across a DST
  boundary that changes mid-project. Getting the epoch-shift arithmetic wrong produces wrong data
  with nothing thrown, which is exactly the failure mode the ticket is written against.
- **Done when:** `toSlotIso` passes a well-formed string through unchanged; given a native `Date`
  and a fake `Zone` it reconstructs `YYYY-MM-DDTHH:mm:ss` + the offset the fake reports, correctly,
  for an instant before 2026-10-25 (CEST→CET) and one after; `parseBookingRow` builds a full
  `BookingRow` from a raw row array using `BOOKINGS_COLUMNS` order, running `toSlotIso` on
  `slot_start` and `slot_end` only. All of it runs under `npm run test:script`.
- **Files:** `apps-script/src/domain/bookings-repo.ts`, `apps-script/src/domain/bookings-repo.spec.ts`
- **Parallel:** yes — only reads from `shared/contract.ts`, which nothing else in this ticket writes

### T2-B — `availabilityFor`

- **Specialist:** implementer
- **Why that one:** the filtering logic is a defined, bounded piece — validate, loop once, filter,
  shape the response — with no open design question once T2-A's seam exists.
- **Done when:** every filtering acceptance criterion has a passing Node test: empty snapshot →
  empty `busy`; a `requested` and a `confirmed` row each produce one range; a `cancelled` row is
  excluded; the serialised response for a populated snapshot contains no `customer_name`,
  `customer_email`, `booking_id` or `service_id` substring anywhere (check this with
  `JSON.stringify(response).includes(...)`, not a hand-rolled object walker); a malformed or
  missing date returns `{ ok: false, error: 'invalid_request' }`.
- **Files:** `apps-script/src/domain/availability.ts`, `apps-script/src/domain/availability.spec.ts`
- **Parallel:** no — imports `parseBookingRow`/`Zone`/`BookingsRepo` from T2-A's file, so it starts after T2-A lands
- **dependsOn:** T2-A

### T2-C — The two adapters

- **Specialist:** implementer
- **Why that one:** mechanical wiring against an interface someone else defined — real code, but
  no design tension, and it cannot be unit tested anyway (Apps Script globals have no Node
  equivalent), so there is nothing here that benefits from extra reasoning depth.
- **Done when:** `SheetBookingsRepo.loadBookingsSnapshot()` reads the `Bookings` tab via
  `SpreadsheetApp`, strips the header row, and returns the rest as `unknown[][]`; `append` throws
  `new Error('implemented in T-03')`; `ScriptZone.offsetFor(instant)` reads
  `Session.getScriptTimeZone()` once and calls `Utilities.formatDate(new Date(instant), tz,
"XXX")`; `eslint.config.js`'s `apps-script/**/*.ts` globals block gains `Session: 'readonly'` and
  `Utilities: 'readonly'`; `npm run lint` and `npm run typecheck` pass.
- **Files:** `apps-script/src/adapters/sheet-bookings-repo.ts`, `apps-script/src/adapters/zone.ts`, `eslint.config.js`
- **Parallel:** yes, alongside T2-B — both depend on T2-A's interfaces but not on each other
- **dependsOn:** T2-A

### T2-D — Wire `doGet`

- **Specialist:** implementer
- **Why that one:** integration of pieces already built and tested elsewhere; the only new
  behaviour is the validate-before-read ordering and the catch-all error mapping.
- **Done when:** `doGet` reads `e.parameter.date` (defaulting to `''` if absent), calls
  `isValidCalendarDate` first and returns `invalid_request` directly without constructing the
  repo or calling `loadBookingsSnapshot()` if it fails; otherwise builds `SheetBookingsRepo` and
  `ScriptZone`, calls `loadBookingsSnapshot()` once, calls `availabilityFor`, and serialises the
  result with `ContentService.createTextOutput(JSON.stringify(result)).setMimeType(ContentService.MimeType.JSON)`;
  the whole body is wrapped in try/catch returning `{ ok: false, error: 'internal_error', message:
... }` on any thrown exception; `doPost` and `notImplemented()` are untouched; `npm run
typecheck` and `npm run script:build` pass (grep the built `Code.js` for `doGet`).
- **Files:** `apps-script/src/main.ts`
- **Parallel:** no — needs both `availabilityFor` (T2-B) and the concrete adapters (T2-C)
- **dependsOn:** T2-B, T2-C
