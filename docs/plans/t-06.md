# T-06 — Specify every state and the exact copy of the booking flow

**Goal:** `docs/design/booking-flow.md` exists, committed, documenting every screen and state of
the booking flow with word-for-word copy, so T-07, T-08, T-09 and T-14 build against it instead of
inventing wording or a visual treatment mid-PR. Three strings the design session never drafted
(past-slot microcopy, name-validation message, confirmation sentence) are recorded as open, with
an owner, rather than invented here.

**Spec:** Agreed in design sync: the flow end to end, every screen's states, and the exact copy for
all of it except those three strings, is already written out in the ticket. This ticket's own work
is turning that into one committed design-spec document in this repo's format (Flow / Screens and
states / Tokens / Layout and responsive / Copy / Accessibility — `agency:writing-specs`), reusing
the token names already declared in `docs/design/tokens.md` rather than inventing new ones, and
writing the three open items as open rather than drafting customer-facing copy nobody has signed
off on.

**Constraints:** Four other tickets build against this document without re-reading the ticket, so
every locked string must be transcribed exactly, not retyped from memory — in particular the
em dash `—` (not a hyphen) and the ellipsis `…` (one character, not three periods) used throughout
the agreed copy. `docs/design/tokens.md` already exists; this ticket references it, it does not
redefine a token. `tools/` scripts in this repo are dependency-free Node ESM with an inline
self-test rather than a separate spec file — see `tools/check-contrast.mjs`.

## Repetition found, and what I did about it

This document locks fourteen exact customer-facing strings, and the whole reason this ticket
exists is that "the confirmation wording sliding from 'requested' back to 'confirmed' in a later
spec review" was named as a real risk earlier in this project. A human re-reading the document on
every PR to check nothing drifted is exactly the manual chore `CONVENTIONS.md` says becomes a
script — and this repo already has two scripts of precisely this shape (`check-contract.mjs`,
`check-contrast.mjs`). `check-copy.mjs` is the third: a small, dependency-free, permanent guard
that fails loudly the moment any of the fourteen locked strings stops appearing verbatim in the
document, wired into `npm run verify` so the drift is caught before a reviewer ever has to notice
it by eye.

## Tasks

### T1 — Build the locked-copy checker

- **Specialist:** implementer
- **Why that one:** bounded, well-defined correctness task (exact substring presence checks)
  with a clear list of expected strings — not a design call, but not pure boilerplate either.
- **Done when:** `node tools/check-copy.mjs` against a real `docs/design/booking-flow.md`
  containing all fourteen locked strings exits 0; against a copy missing even one of them, it
  exits 1 and names exactly which string is missing; against a missing file it exits 1 with a
  clear message (no bootstrap grace period — the real document lands in this same pull request);
  `npm run check:copy` exists and is wired into `verify`; lint/format/typecheck stay clean.
- **Files:** `tools/check-copy.mjs`, `package.json`
- **Parallel:** yes — touches no file T2 or T4 touch, and does not need the real document to
  exist yet (prove it against a throwaway fixture, the same way `check-contrast.mjs`'s author
  proved that script before the token document existed)

### T2 — Write the booking-flow specification

- **Specialist:** deep-implementer
- **Why that one:** the document's structure and most of its copy are already decided, but
  writing the three open items well — stating clearly what's missing, why, who owns it, and what
  shape the eventual answer needs to take — is a real judgement call, and the whole point of this
  ticket is that nobody downstream invents a visual treatment or a sentence the room hasn't seen.
  Getting the open items vague is exactly the failure mode this ticket exists to prevent.
- **Done when:** `docs/design/booking-flow.md` exists with every section in its brief, the
  fourteen locked strings transcribed exactly (not retyped), the three open items named with an
  owner rather than drafted, and `node tools/check-copy.mjs` (once T1 lands) passes against it.
- **Files:** `docs/design/booking-flow.md`
- **Parallel:** yes — touches no file T1 or T4 touch

### T3 — Point CONVENTIONS and README at the new document

- **Specialist:** mechanical
- **Why that one:** the decision (where this kind of document lives, and that it should be
  linked) is already made by precedent — `docs/design/tokens.md` got the identical treatment in
  the previous ticket. This is applying that pattern once more, not deciding anything.
- **Done when:** `CONVENTIONS.md`'s "Where things go" list has a line for booking-flow state and
  copy pointing at `docs/design/booking-flow.md`, and `README.md`'s "More" list links it.
- **Files:** `CONVENTIONS.md`, `README.md`
- **Parallel:** yes — touches no file T1 or T2 touch

### T4 — Critic pass

- **Specialist:** critic
- **Why that one:** adversarial, read-only check that the document actually satisfies every
  acceptance criterion before this goes into a pull request — this is the one document three
  other tickets build against without re-reading the ticket.
- **Done when:** a findings list exists (empty if none survive) covering: every locked string
  present verbatim including exact punctuation, the shared-component-with-a-`reason`-prop framing
  (not three separate empty states), the 14-day next-open-day bound and its phone-number
  fallback, the three open items each carrying a named owner rather than invented copy, and that
  `npm run check:copy` and `npm run verify` actually pass.
- **Files:** none (read-only)
- **Parallel:** no — needs T1 and T2 finished
