# T-01 — Stop a retried booking being told its own slot is taken

**Goal:** `booking_id` is a client-generated idempotency key documented across the contract, the
sheet template and a manifest test, so T-03/T-08/T-11 can build against a settled shape.
**Spec:** Amend `shared/contract.ts` (add `BookRequest.booking_id`, reframe
`BookSuccessResponse.booking_id` as an echo, document the three-way replay rule, add
`SALON_TIMEZONE`), update `docs/sheet-template.md`'s `booking_id` row, and add
`apps-script/src/manifest.spec.ts` asserting the manifest's `timeZone` matches `SALON_TIMEZONE`.
Document only — T-03 implements the replay rule.
**Constraints:** Six `BookingErrorCode` values, no new one. No `idempotency_key` field — `booking_id`
is the one identifier. No edits to `main.ts` or any frontend file. `tools/check-contract.mjs` stays
untouched — no column is added, removed or reordered, only prose around an existing column changes.

## Files

| File | Responsibility |
|---|---|
| `shared/contract.ts` | change — `booking_id` on `BookRequest`, updated comment on `BookSuccessResponse.booking_id`, three-way replay rule as comments, new `SALON_TIMEZONE` export |
| `docs/sheet-template.md` | change — `booking_id` row's "Who writes it" cell and a notes bullet, reframed as client-supplied |
| `apps-script/src/manifest.spec.ts` | new — fails if `appsscript.json`'s `timeZone` and `SALON_TIMEZONE` drift |

No repetition found worth scripting — this is one coherent edit to two files plus one new test,
not a sweep. `tools/check-contract.mjs` already does the cross-file drift-checking this ticket
would otherwise reinvent; nothing here duplicates it.

A real resolution risk worth flagging before dispatch rather than discovering after: nothing in
`apps-script/` currently imports from `shared/contract.ts` (grepped for `@contract`, zero hits),
and `apps-script/vitest.config.mts` has no alias/tsconfig-paths plugin wired in, unlike the
Angular build (which resolves `@contract/*` natively). The new spec file must import
`SALON_TIMEZONE` with a plain relative path (`../../shared/contract`), not the `@contract/*`
alias used elsewhere, or the test risks failing to resolve at run time on a path nobody has
exercised yet.

## T1 — Amend `shared/contract.ts`

- **Specialist:** implementer
- **Why that one:** small surface, but real judgement on wording and placement — this file is the
  one both runtimes import, so imprecise comments here are the thing every later ticket reads.
- **Done when:**
  - `BookRequest` gains `booking_id: string;` next to `access_token`, with a comment explaining it
    is client-generated and exists so a retried request can prove it's the same request.
  - `BookSuccessResponse.booking_id`'s comment is rewritten to say it is now an echo of the
    request's `booking_id`, not server-minted.
  - A new comment block states the three-way replay rule precisely: `booking_id` + verified email
    + slot all match an existing row → return the original success, write nothing; `booking_id` +
    email match but slot differs → `invalid_request`; `booking_id` not a well-formed UUID →
    `invalid_request`, never treated as a fresh booking. Also state plainly that a same-`booking_id`
    collision is expected client behaviour (T-08 retries once automatically), not a pathological
    case, and that this replay rule is the only read-back this system has, since there is no
    bookings-lookup endpoint.
  - A new section (placed immediately before `// ===== Sheet shapes =====`) exports
    `SALON_TIMEZONE = 'Europe/Zagreb'`, with a comment stating it is the one literal that exists
    twice in this system — here and in `apps-script/src/appsscript.json`'s `timeZone` field, which
    Apps Script reads directly and cannot import TypeScript — and that a Node test keeps the two in
    sync.
  - No existing export is renamed, removed, or reordered. `npm run typecheck` passes.
- **Parallel:** yes — touches only this file.

## T3 — `apps-script/src/manifest.spec.ts`

- **Specialist:** test-writer
- **Why that one:** covering a drift that must not happen, against behaviour T1 just defined —
  no implementation logic to design, just a precise assertion.
- **Done when:**
  - New file reads `apps-script/src/appsscript.json` via `node:fs` + `JSON.parse` (same technique
    as `tools/check-contract.mjs`, not a JSON import — the apps-script `tsconfig.json` has no
    `resolveJsonModule`), and imports `SALON_TIMEZONE` from `shared/contract.ts` via the relative
    path `../../shared/contract` (not the `@contract/*` alias — see the resolution risk noted
    above).
  - One test (`describe`/`it`, matching `slots.spec.ts`'s style) asserts
    `manifest.timeZone === SALON_TIMEZONE`.
  - Runs under `npm run test:script` and passes once T1 has landed `SALON_TIMEZONE`.
  - Before finishing, manually edit one side of the pair locally (either the manifest's `timeZone`
    or the test's expectation) to confirm the test actually fails, then revert that edit — this
    proves the test is wired to both files, not just one. Report in the task result that this was
    done, not just the final passing state.
- **Parallel:** no — depends on T1 for `SALON_TIMEZONE` to exist.
