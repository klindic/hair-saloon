# T-10 — Fail the build if a credential leaks into the bundle

**Goal:** `npm run verify` fails if the built browser bundle contains anything
shaped like a Google API key, a Google OAuth client secret, or a
service-account private key, and passes when it does not — with no new CI
workflow step.

**Spec:** A new script, `tools/check-no-secrets.mjs`, walks every file under
`BROWSER_DIST_DIR` (from `tools/dist-dir.mjs`), matches three fixed patterns,
and exits non-zero on a hit, printing file, pattern name and byte offset but
never the full matched string. Wired into the `verify` chain in `package.json`
after `check:pages`, not into a workflow. The `config.json`-extra-key half of
the original ticket is already built (`tools/check-contract.mjs`) and is out
of scope here.

**Constraints:** Follow the existing `tools/*.mjs` style (`check-contract.mjs`,
`check-pages-build.mjs`) — plain Node ESM, no dependency, `REPO_ROOT` from
`dist-dir.mjs` for relative paths in output, `console.error` + `process.exit(1)`
on failure, one success line on `console.log` otherwise. No automated test
file: sibling scripts in `tools/` have none: they are proven by running them,
and the ticket's own "Tests" section asks for exactly that, by hand, recorded
in the PR. Do not scan `node_modules` or source, only the build artefact. No
allowlist file.

## T1 — Write the secret-scanning script

- **Specialist:** implementer
- **Why that one:** real logic (directory walk, three regex patterns, byte
  offset reporting, truncated output) with a few edge cases to get right, but
  the approach, the patterns and the file layout were already decided in
  grooming — nothing left to design.
- **Done when:** `tools/check-no-secrets.mjs` exists, follows the house style
  of `tools/check-contract.mjs` and `tools/check-pages-build.mjs`, and:
  - recursively walks every file under `BROWSER_DIST_DIR`
  - matches each file's contents against all three patterns: Google API key
    (`AIza[0-9A-Za-z\-_]{35}`), Google OAuth client secret
    (`GOCSPX-[A-Za-z0-9_-]+`), and a service-account marker (either
    `-----BEGIN PRIVATE KEY-----` or `"type": "service_account"`)
  - on any match, records the file path (relative to `REPO_ROOT`), the pattern
    name and the byte offset (`match.index`), and a truncated preview of the
    match (first 4 and last 4 characters only, joined with `…` — never the
    full string)
  - prints every finding to `console.error` and exits with a non-zero code if
    there is at least one
  - prints one success line to `console.log` and exits 0 if there are none
  - run by hand against the real build (`npm run build` first) and verified to
    pass; then a throwaway file containing a fake `AIza`-shaped string is
    written into `BROWSER_DIST_DIR`, the script is re-run and verified to fail
    with a non-zero exit and a truncated (not full) string in its output, and
    the throwaway file is deleted afterwards
- **Parallel:** yes — only new file, nothing else touches it
- **Depends on:** nothing
