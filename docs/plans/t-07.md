# T-07 — Paint the day's bookable slots with no network round trip

**Goal:** A customer can open the site, see the demo-mode banner and a disabled
sign-in control when unconfigured, pick a day, and see that day's candidate
slots (or a closed/no-slots card with a next-open-day escape hatch) computed
entirely from the compiled-in `hours.json`/`services.json` — no network call,
no timezone conversion (that is T-08's job via `salon-time.ts`).

**Spec:** Issue #8, as corrected in grooming: criterion 3/6 moved all timezone
math out of this ticket (wall-clock only); closed-day/closure handling and the
`DayUnavailableCard` component (reused unmodified by T-14) were added; fonts
are self-hosted from npm, copied out of `node_modules` via an explicit
`angular.json` assets entry because `@import`-ing a Fontsource package's CSS
from Sass does not reliably get its relative `./files/*.woff2` references
resolved and copied by Angular's build — confirmed by inspecting the installed
packages (`@fontsource-variable/fraunces@5.3.0`, `@fontsource/work-sans@5.3.0`):
both packages' CSS references files via paths relative to their own location in
`node_modules`, which is not where the built app serves assets from.

**Constraints:** Standalone components, signals, `OnPush` (the schematic
default), no `NgModule`. No `.component.ts` suffix; selectors are `app-`
kebab-case. Tests beside the code as `*.spec.ts`. `features` never import each
other; cross-feature-reusable code goes in `core`. No value here is final
design — colours/spacing/exact microcopy that T-06 (design tokens) or T-05
(flow/copy spec) will own are placeholder, tagged `// TODO(T-06)` or
`// TODO(T-05)` inline, per the team's agreement that structural work starts
before the design tickets land.

## Repetition check

No script-worthy repetition found. Five small presentational components differ
enough in markup and behaviour that a generator would be more code than it
saves. The font setup touches `angular.json` once; it is not a repeated manual
chore, so it doesn't earn a `tools/` script beyond the verification check
(`check-fonts-build.mjs`), which itself follows the existing `check-pages`
pattern rather than inventing a new one.

## Tasks

### T1 — Scheduling domain functions

- **Specialist:** implementer
- **Why that one:** real logic with explicitly enumerated edge cases, but the
  approach (pure functions, no Angular, mirrors `apps-script/src/domain/slots.ts`'s
  style) is already decided.
- **Done when:** `computeDaySlots`, `isDayOpen`, `findNextOpenDay`,
  `formatNextOpenDayLabel` exist with the signatures and edge-case tests in the
  brief, `scheduling.spec.ts` passes under `npm run test`.
- **Parallel:** yes — new files only.

### T2 — Demo-mode banner and sign-in control shell

- **Specialist:** implementer
- **Why that one:** straightforward signal-driven conditional rendering
  following the existing `ConfigService` pattern; no novel design.
- **Done when:** blank `config.json` shows the exact banner copy and a
  disabled sign-in control with placeholder explanatory text; filled
  `config.json` hides the banner; both have passing specs.
- **Parallel:** yes — touches only `core/layout/*` and the root shell, which
  no other task touches.

### T3 — Day picker and slot grid components

- **Specialist:** implementer
- **Why that one:** defined presentational components with clear inputs/outputs,
  no business logic of their own.
- **Done when:** `DayPicker` renders a configurable number of day buttons and
  emits a date key; `SlotGrid` renders a list of HH:mm buttons and emits the
  selected one; both have passing specs; neither imports `scheduling.ts`
  (kept fully decoupled so this task has zero dependency on T1).
- **Parallel:** yes — new files only, no shared types with T1.

### T4 — Day-unavailable card with focus management

- **Specialist:** deep-implementer
- **Why that one:** the real design tension in this ticket — moving focus
  correctly after an async re-render, across two different "next unavailable
  day" outcomes, without ever leaving focus on a removed element. Worth
  getting right the first time rather than reviewing it into shape.
- **Done when:** the component renders the closed-day copy exactly, offers the
  next-open-day link or the phone fallback per the 14-day rule, and a test at
  a level that can observe real DOM focus proves focus lands on the slot grid
  or the next card after activation.
- **Parallel:** yes — new files (`day-unavailable-card/*`, `src/data/contact.json`,
  a small addition to `src/data/README.md`), none shared with other tasks.

### T5 — Self-hosted fonts and the build-output check

- **Specialist:** implementer
- **Why that one:** the design decision (copy specific files via an explicit
  assets glob, hand-write `@font-face` against the copied paths rather than
  trust a vendor `@import`) is already made and verified against the actual
  installed packages; this is executing that decision carefully, not deciding it.
- **Done when:** `npm run build:pages` output contains the referenced
  `.woff2` files at the documented paths, `check:fonts` fails on a build
  missing them, and it runs inside `npm run verify`.
- **Parallel:** yes — touches `angular.json`, `package.json`, `src/styles.scss`,
  `src/styles/fonts.scss`, `tools/check-fonts-build.mjs`; no other task touches
  any of these.
